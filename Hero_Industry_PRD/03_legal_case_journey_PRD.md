# 03. Legal Case Journey — 개발 PRD

> 문서 버전: 1.0 · 2026-11-03 · 목적: 독립 실행 가능한 고급 업종별 인터랙티브 히어로

## 1. 프로젝트 정의
- **적합 업종:** 법무사·법률 사무소
- **사용자 가치:** 등기·상속·법인 설립 절차를 문서·장면 오브젝트로 시각화하여 상담으로 연결
- **핵심 CTA:** 업무 상담 신청
- **대표 사용자 여정:** 상황 선택→절차 이해→준비 서류→상담
- **벤치마킹 출발점:** https://www.legalzoom.com/ (제품/서비스 UX 원리 참고, 구현·디자인 복제 금지)

## 2. 장면 및 UI 설계
- **첫 장면:** 제목(핵심 서비스 가치), 짧은 설명, 1차 CTA, 3D 대형 비주얼, 조작 가이드, 로딩 포스터.
- **조작 영역:** 실제 변경 가능한 컨트롤을 3D 캔버스 밖 HTML로 제공. 선택 상태/되돌리기/초기화/전체화면 버튼 포함.
- **전환 영역:** 선택한 콘텐츠의 요약 패널과 상담·예약·구매 CTA, 모바일에는 바텀시트 구성.
- **필수 3D 자산:** 문서·도장·파일폴더·건물 아이콘 3D GLB 또는 절차적 메시
- **디자인:** 포인트 컬러 1개+뉴트럴 배경, 핵심 메시지와 CTA가 입자/3D 효과에 가려지지 않도록 대비 유지.

## 3. 핵심 인터랙션 7개 — 구현 명세
1. **Service Selector**: 상속등기/부동산등기/법인설립 선택 시 절차 장면과 문구를 변경한다.
2. **3D Document Stack**: 선택 업무의 필수 문서 모형이 카드 스택 형태로 등장하고 클릭하면 설명이 뜬다.
3. **Process Timeline Camera**: GSAP 카메라 이동으로 접수→검토→제출→완료 단계를 순서대로 탐색한다.
4. **Dependency Highlight**: 단계 클릭 시 선행 작업과 연결선을 밝히고 현재 위치를 명확히 표시한다.
5. **Checklist Interaction**: 사용자가 보유 서류 체크박스를 선택하면 준비 현황을 보여주되 법적 완비 판정은 하지 않는다.
6. **Privacy-first Intake**: 민감한 사건 상세를 히어로에서 요구하지 않고 일반 문의·예약으로만 연결한다.
7. **Estimated Process Disclaimer**: 기간·비용은 조건에 따라 달라질 수 있음을 명시하고 확정 견적 대신 상담 CTA를 제공한다.

## 4. 상태·데이터 계약
- `selectedId`: 현재 선택 객체/서비스/상품. `viewMode`: 카메라·레이어 모드. `config`: 사용자 변경 값. `isAnimating`: 이동 중 상태.
- 모든 3D Mesh에는 안정적인 ID를 부여하고, HTML 상태 패널과 동일한 데이터에서 렌더링한다.
- 가격·재고·매물·시간표 등 외부 변경 데이터는 별도 adapter를 통해 주입한다. 데모에서는 `mockData`와 `DEMO` 라벨을 사용한다.
- 모델 교체 시 메시 이름/좌표/단위/재질 슬롯/애니메이션 클립을 검증하는 자산 체크리스트를 둔다.

## 5. 구현 우선순위 및 테스트 시나리오
- **P1 필수:** 기본 포스터·키보드 가능한 CTA·의미 있는 HTML 제목·3D 기본 장면.
- **P2 필수:** Service Selector, 3D Document Stack, 선택 상태 패널.
- **P3 권장:** Process Timeline Camera, Dependency Highlight, Checklist Interaction.
- **P4 고급:** Privacy-first Intake, Estimated Process Disclaimer, 모바일·저사양 폴백.
- **E2E-01:** 첫 화면 → 상황 선택 → 절차 이해 → 준비 서류 → 상담 → CTA 도달.
- **E2E-02:** 빠른 선택 변경/뒤로가기/복귀에도 선택 상태와 실제 3D 표현이 일치.
- **E2E-03:** 3D 로딩 실패·WebGL 비지원·모션 감소 환경에서 핵심 내용/CTA 유지.

## 6. 업종별 신뢰성·주의사항
- 법률 결과 보장 금지. 법무사 업무 범위를 넘는 법률 대리/상담으로 오해되지 않게 법률전문가 검토 필요.

## 7. 수익화/실무 연결
- **사업 목표:** 사용자가 3D 경험 후 **업무 상담 신청** 행동을 수행하도록 하는 전환형 히어로.
- **측정 이벤트:** `hero_view`, `hero_interact`, `hero_select`, `hero_cta_click`, `lead_submit`(개인정보 제외).
- **권장 A/B 테스트:** 자동 투어 vs 바로 조작, 3D 히어로 vs 정적 이미지, CTA 상단 고정 vs 선택 후 표시.
- **초기 검증:** 실제 고객 5명 이상에게 조작 성공 여부와 상담/구매 의사 측정. 수치 목표는 프로젝트 착수 시 기준선 설정.


## 공통 실행 계약
- **형태:** Next.js App Router + React + TypeScript + Tailwind CSS + shadcn/ui. Three.js/R3F는 3D가 필요한 영역에만 client component로 로드한다. React 19 환경이면 @react-three/fiber 9 계열 호환을 확인한다.
- **모델 파이프라인:** Blender/Rhino 8/Fusion 360 → GLB(glTF 2.0), 실무 자산은 라이선스·소유권을 점검한다. 3D 파일이 없으면 대체용 기본 메쉬를 먼저 만들고, 실제 모델 교체 인터페이스를 유지한다.
- **공통 레이아웃:** 상단 로고/메뉴, 좌측 핵심 제목·근거 문구·CTA, 우측 또는 배경 3D Canvas, 하단 상태/선택 요약. 1440/1024/768/390px에서 반응형 검증한다.
- **품질:** 첫 화면 LCP와 CLS 측정, 저사양은 정적 포스터+기본 HTML 폼 제공, 60fps 지향(절대 보장 아님), DPR 상한·지연 로딩·프리로드·메모리 자원 해제, `prefers-reduced-motion`, 키보드/스크린리더 대안 필수.
- **안전·정확성:** 화면 수치·가격·의료/법률 정보는 데모임을 명시하고 실제 데이터와 분리한다. 개인정보 입력 전 최소 수집·동의·보관 정책 확인. CTA는 클릭 가능한 실제 동작(데모에서는 검증 가능한 폼/확인 상태)으로 만든다.

## 권장 파일 구조
```text
app/(demos)/[slug]/page.tsx
components/heroes/[HeroName]/Hero.tsx
components/heroes/[HeroName]/Scene.tsx
components/heroes/[HeroName]/Overlay.tsx
components/heroes/[HeroName]/controls.tsx
components/heroes/[HeroName]/config.ts
components/heroes/[HeroName]/types.ts
public/models/[slug]/
public/posters/[slug]/
```
파일명과 컴포넌트 이름은 해당 프로젝트에 맞게 치환한다. Scene은 클라이언트 전용으로 동적 로딩하고, 폼/콘텐츠는 가능하면 HTML로 렌더링한다.

## 단계별 개발 지시 (P0–P6)
- **P0 조사·자산 계약:** 3D 모델 메시 이름, 정점/재질/애니메이션, 단위·축·폴리곤 수, 데이터 소스, 법적 문구를 문서화한다.
- **P1 정적 와이어프레임:** 모바일 포함 타이포·CTA·상태 패널·포스터 폴백을 만든다.
- **P2 3D 기초:** GLB 로딩, 조명, 카메라 한계, 로딩·에러·fallback 처리한다.
- **P3 핵심 인터랙션:** 아래 7개를 독립적으로 구현하고 상태를 한 곳에서 관리한다.
- **P4 업무 전환:** CTA, 문의/견적/예약/상담 폼을 실제 조작 가능한 데모 흐름으로 연결한다.
- **P5 검증:** 마우스·터치·키보드, 느린 네트워크, WebGL 실패, 화면 크기 변경, 빠른 연타, 언마운트 메모리 해제를 테스트한다.
- **P6 산출:** `README.md`, 모델 교체 가이드, 제어 옵션 표, 완료/미완료 목록, 성능 측정 결과와 캡처를 남긴다.

## 공통 검수 체크리스트
- [ ] 첫 로드에서 CTA가 즉시 보이고 3D 실패 시 포스터/폼이 남는다.
- [ ] 모든 선택 컨트롤은 시각적 상태뿐 아니라 읽을 수 있는 텍스트 상태를 제공한다.
- [ ] 드래그와 페이지 스크롤이 터치 기기에서 충돌하지 않는다.
- [ ] 포커스 복귀·ESC/닫기·키보드 조작이 가능하다.
- [ ] 컴포넌트를 여러 번 열고 닫아도 RAF/리스너/Geometry/Material 누수가 없다.
- [ ] 불확실한 수치·효과·가격·법적 주장에는 검증 가능한 출처 또는 데모 표시가 있다.
- [ ] 데스크톱과 모바일에서 CTA 제출·선택·상태 저장 흐름을 끝까지 테스트한다.

## Claude Code / Codex 실행 프롬프트
> 이 PRD를 단일 진실원(source of truth)으로 사용하라. P0에서 자산·데이터·법률 문구의 불확실성을 확인하고, 없는 3D 모델은 독창적인 임시 GLB/절차적 메쉬로 대체하라. P1~P6를 순서대로 구현하되 매 단계 lint/typecheck/build 및 검수 항목을 확인하라. 코드를 실제로 실행해 확인하지 못하면 '미검증'이라고 명시하라. 3D 연출보다 사용자 목적과 CTA의 정상 동작을 우선하라. 최종적으로 사용법, 교체할 자산 목록, 미구현 사항을 README에 정리하라.
